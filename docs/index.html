DeskAccess

TPM-aware, passwordless access control for RDP, SSH, VNC, and selected TCP services. Keep RDP private, then allow access only from authenticated machine identities with optional TPM-backed identity keys.

Selected services only

Share RDP, SSH, VNC, or a custom TCP port without exposing an entire subnet.

Invite and pairing links

Create temporary links or persistent paired access for trusted admin devices.

Encrypted transport

Service data is carried over encrypted peer connections between DeskAccess endpoints.

Built for system administrators

DeskAccess is for teams that want to stop exposing RDP directly and avoid broad VPN access. Administrators can keep RDP bound to a private or loopback address and require DeskAccess authentication before any client reaches it.

Replace exposed RDP entry points

Use DeskAccess as the controlled access path to RDP instead of opening port 3389 to a LAN, VPN subnet, or the public internet.

TPM-backed identity keys

Where TPM support is available, trusted access can require proof from hardware-backed key material so only the paired machine identity can reconnect.

Machine identity access

Pairing and reconnects use machine identity proofs at the DeskAccess layer, reducing dependence on shared remote-access passwords.

Alternative to broad remote access tools

DeskAccess is built for people comparing VPN and remote desktop products who want a narrower model: access to one selected service instead of a whole private network.

VPN alternative

Use DeskAccess when you need RDP, SSH, VNC, or TCP access without broad subnet routing.

Remote desktop alternative

DeskAccess can launch existing RDP and VNC clients through a secure tunnel.

Self-hostable alternative

Run your own relay infrastructure when you want control over availability and policy.

People comparing TeamViewer, AnyDesk, RustDesk, Chrome Remote Desktop, Tailscale, ZeroTier, or traditional VPNs may choose DeskAccess for service-scoped remote access.

Hardware-backed, passwordless authentication

DeskAccess uses passwordless authentication at the DeskAccess layer. During pairing and reconnect, endpoints prove machine identity instead of relying on a shared DeskAccess password.

Private RDP by default

RDP can remain reachable only locally on the host while DeskAccess handles the authenticated remote access path.

TPM-backed identity

Where supported, DeskAccess can bind machine identity to TPM-backed key material. This is used as a hardware-backed identity key, not as full TPM manufacturer-chain attestation or device-health verification.

Passwordless pairing

Pairing links establish trust between machines. Later connections authenticate with machine identity proofs, not a DeskAccess account password.

Software fallback

On systems without TPM support, DeskAccess can fall back to software identity while keeping the same machine-identity authentication model.
