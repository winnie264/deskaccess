DeskAccess

An open-source, passwordless remote access alternative for RDP, SSH, VNC, and selected TCP services, using machine certificates and optional TPM-backed hardware identity without opening access to the whole private network.

Selected services only

Share RDP, SSH, VNC, or a custom TCP port without exposing an entire subnet.

Invite and pairing links

Create temporary links or persistent paired access for trusted admin devices.

Encrypted transport

Service data is carried over encrypted peer connections between DeskAccess endpoints.

Alternative to broad remote access tools

DeskAccess is built for people comparing VPN and remote desktop products who want a narrower model: access to one selected service instead of a whole private network.

VPN alternative

Use DeskAccess when you need RDP, SSH, VNC, or TCP access without broad subnet routing.

Remote desktop alternative

DeskAccess can launch existing RDP and VNC clients through a secure tunnel.

Self-hostable alternative

Run your own relay infrastructure when you want control over availability and policy.

People comparing TeamViewer, AnyDesk, RustDesk, Chrome Remote Desktop, Tailscale, ZeroTier, or traditional VPNs may choose DeskAccess for service-scoped remote access.

Hardware-backed, passwordless authentication

DeskAccess uses passwordless authentication at the DeskAccess layer. During pairing and reconnect, endpoints prove machine identity with certificates instead of relying on a shared DeskAccess password.

TPM-backed certificates

Where supported, DeskAccess can bind machine identity to TPM-backed key material so trusted access is tied to the hardware device.

Passwordless pairing

Pairing links establish trust between machines. Later connections authenticate with certificates, not a DeskAccess account password.

Software fallback

On systems without TPM support, DeskAccess can fall back to software identity while keeping the same certificate-based authentication model.
